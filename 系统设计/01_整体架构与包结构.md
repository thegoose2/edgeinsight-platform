## 1. 文档概述

### 1.1 设计背景

本文档是 EdgeInsight Platform 的系统架构设计文档，作为业务架构文档（V1.3）的下游输出。当前版本覆盖第一个可交付小闭环：**设备管理 → 设备接入 → 数据接收 → 数据存储**。

### 1.2 本版本范围

**覆盖模块**

| 模块 | 说明 |
|------|------|
| 设备类型与测点模板管理 | DeviceType 及测点模板 CRUD |
| 设备注册与管理 | 设备档案、批量导入、生命周期管理 |
| 协议档案管理 | ProtocolProfile 配置与维护 |
| 设备接入认证 | MQTT 认证，基于 connect_id 白名单 |
| 数据接收与解析 | MQTT 消息接收、解析器路由、ParsedMessage 输出 |
| 数据存储与查询 | 遥测数据写入、最新值查询、历史数据查询 |
| 在离线管理 | 连接状态维护、历史记录、统计查询 |

**明确延后**

- 告警引擎（TelemetryReceivedEvent 已预留订阅点）
- WebSocket 实时推送（DeviceStatusChangedEvent 已预留）
- 设备控制（下行指令通道架构已预留）
- JWT 鉴权（本迭代使用固定 Token）
- TCP 协议接入（扩展点①已预留）
- 数据导出

### 1.3 已确认技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 应用框架 | Spring Boot | 团队 Java 技术栈，标准 Spring 生态 |
| MQTT Broker | Moquette（内嵌） | 纯 Java 实现，随应用启动，无需独立部署 |
| 数据库 | MySQL | 业务数据与采集数据统一存储，V1.0 |
| 部署形态 | 两个进程 | Spring Boot 应用（内嵌 Moquette）+ MySQL 实例 |
| 部署环境 | 私有化内网 | 支持 Windows，不依赖任何公有云服务 |

### 2.2 内部事件总线

Platform 内部模块通过 **Spring ApplicationEvent（异步模式）** 解耦，三条核心链路互不阻塞：

| 事件 | 发布者 | 订阅者 | 触发时机 |
|------|------|------|------|
| `TelemetryReceivedEvent` | TelemetryIngestService | AlarmEngine、WebSocketPushService | 遥测数据写库后 |
| `AlarmTriggeredEvent` | AlarmEngine | WebSocketPushService、AndonClient | 告警规则命中后 |
| `DeviceStatusChangedEvent` | OnlineStatusService | WebSocketPushService、AlarmEngine | 在离线状态变更后 |
| `CommandResultEvent` | MqttMessageListener | ControlService | 收到指令执行结果后 |

事件类均位于 `event/` 包，作为中性的 POJO，发布者与订阅者均依赖它，但彼此不直接依赖。

### 2.3 外部系统交互

| 外部系统 | 方向 | 交互方式 | 说明 |
|------|------|------|------|
| EdgeInsight View | 双向 | REST API + WebSocket | View 调 REST 查询控制，Platform 通过 WS 主动推送 |
| GetInsight Andon | 单向（Platform → Andon） | HTTP POST | 告警触发后推送，由 Andon 负责多渠道通知 |
| EdgeInsight Connect | 双向 | MQTT 专属协议 | 上行数据通道 + 下行指令通道，两条独立通道 |

## 3. 模块结构设计

采用 **Maven 多模块**结构，通过模块边界在编译期强制执行依赖方向，避免单模块依赖方向靠约定、靠自觉的问题。`edgeinsight-parser-spi` 可独立发布，解析器库仓库直接引用该模块开发解析器，无需依赖整个平台。

### 3.1 模块总览

```
edgeinsight-platform/                      ← 父 POM，统一版本管理
  │
  ├── edgeinsight-common/                  ← 公共模型与事件（无业务依赖）
  ├── edgeinsight-parser-spi/              ← 解析器契约（可独立发布）
  ├── edgeinsight-adapter-spi/             ← 适配器契约
  ├── edgeinsight-core/                    ← 核心业务逻辑 + 数据访问
  ├── edgeinsight-adapter-mqtt/            ← MQTT 接入实现
  ├── edgeinsight-api/                     ← REST 接口层
  └── edgeinsight-app/                     ← 启动装配，最终打包
```

### 3.2 各模块详细结构

**强制规则（由 Maven 模块边界在编译期保障）：**

- `parser-spi` 不得依赖 `core`，确保解析器库可独立引用
- `core/domain` 只依赖 `repository/spi`，不得直接引用 `jpa/` 实现类
- `common` 和 `parser-spi` 不得引入任何业务依赖
- `app` 模块不写任何业务代码，只做 Bean 装配和配置

### 3.4 ResolvedContext 结构

每台设备连接建立时从数据库加载，缓存在内存中，消息处理热路径全部读缓存，不查库。

```java
ResolvedContext {
    long    deviceId          // telemetry_record 写入用
    long    deviceTypeId      // 备用
    String  parserId          // 路由到对应解析器
    String  protocol          // MQTT / TCP，Adapter 层分发
    Set<String> validPointCodes  // 测点白名单，未注册测点直接丢弃
    String  lifecycleStatus   // ACTIVE / INACTIVE，INACTIVE 时数据丢弃
    int     gracePeriodSecs   // 断连宽限期，从 system_config 按协议读取
}
```

**缓存加载时机：** 设备连接建立（认证通过后）

**缓存清除时机（主动精准清除）：**

| 操作 | 清除范围 |
|------|------|
| 修改 device.device_type_id | 该 connectId |
| 修改 device.lifecycle_status | 该 connectId |
| 修改 device_type.profile_type | 该 device_type 下所有 connectId |
| 增删 device_type_point | 该 device_type 下所有 connectId |

清除后不主动重建，下一条消息到达时触发懒加载。
