## 1. 总体说明

- 数据库：MySQL
- 业务数据与采集数据统一存储于同一 MySQL 实例
- 数据访问层通过 `TelemetryRepository` 抽象接口隔离，V1.0 使用 MySQL 实现，未来可替换为时序数据库（预估迁移工作量：一人一到两周）
- `telemetry_record` 表按月分区，到期整分区 DROP，不做 DELETE 清理

## 2. 表结构设计

### 2.1 protocol_profile（协议档案）

每种网关型号或设备接入方式一条记录，研发预置，交付工程师选用。

```sql
CREATE TABLE protocol_profile (
    profile_type        VARCHAR(50)     NOT NULL COMMENT '协议档案标识，主键，如 INTGATHER-V2、TCP-DEVICE-A',
    protocol            VARCHAR(10)     NOT NULL COMMENT '协议类型：MQTT / TCP',
    parser_id           VARCHAR(100)    NOT NULL COMMENT '使用的解析器标识，对应 ParserRegistry 中注册的解析器',
    topic_patterns      JSON            COMMENT 'MQTT 专用，主题匹配规则，如 {"telemetry": "ei/{gw}/telemetry"}',
    msg_type_mapping    JSON            COMMENT 'payload 中消息类型字段的值到消息分类的映射',
    frame_strategy      VARCHAR(50)     COMMENT 'TCP 专用，分帧策略，如 LENGTH_PREFIX',
    description         VARCHAR(200)    COMMENT '描述',
    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by          VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '创建人用户名（JPA Auditing 自动填充）',
    updated_by          VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '最后修改人用户名（JPA Auditing 自动填充）',
    PRIMARY KEY (profile_type)
) COMMENT '协议档案，每种网关型号一条，研发预置';
```

**初始数据（智采极标准协议）：**

```sql
INSERT INTO protocol_profile VALUES (
    'INTGATHER-V2', 'MQTT', 'intgather-v2-default',
    '{"telemetry":"ei/{gw}/telemetry","status":"ei/{gw}/status","command":"ei/{gw}/command","reply":"ei/{gw}/command/reply"}',
    NULL, NULL, '智采极 V2 标准协议', NOW(), NOW()
);
```

### 2.2 device_type（设备类型）

设备类型模板，同型号设备共享测点定义。

```sql
CREATE TABLE device_type (
    id              BIGINT          NOT NULL AUTO_INCREMENT,
    type_code       VARCHAR(50)     NOT NULL COMMENT '类型编码，唯一，如 CNC-MAZAK-V3',
    name            VARCHAR(100)    NOT NULL COMMENT '类型名称，如 马扎克 CNC V3',
    profile_type    VARCHAR(50)     NOT NULL COMMENT '该类型设备默认使用的协议档案',
    description     VARCHAR(200)    COMMENT '描述',
    created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by      VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '创建人用户名（JPA Auditing 自动填充）',
    updated_by      VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '最后修改人用户名（JPA Auditing 自动填充）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_type_code (type_code),
    FOREIGN KEY (profile_type) REFERENCES protocol_profile(profile_type)
) COMMENT '设备类型，测点模板的持有者';
```

**删除约束：** 有关联设备时不允许删除，无关联设备时允许删除（级联删除其 device_type_point 记录）。

### 2.3 device_type_point（测点模板）

设备类型的测点定义，是所有同类型设备测点的权威来源（策略 A）。

```sql
CREATE TABLE device_type_point (
    id              BIGINT          NOT NULL AUTO_INCREMENT,
    device_type_id  BIGINT          NOT NULL COMMENT '所属设备类型',
    point_code      VARCHAR(50)     NOT NULL COMMENT '测点编码，同设备类型内唯一',
    name            VARCHAR(100)    NOT NULL COMMENT '测点名称，如 进口温度',
    data_type       ENUM('DOUBLE','STRING','BOOLEAN') NOT NULL DEFAULT 'DOUBLE' COMMENT '数据类型',
    unit            VARCHAR(20)     COMMENT '单位，如 ℃、MPa、A',
    range_min       DECIMAL(20,6)   COMMENT '量程下限',
    range_max       DECIMAL(20,6)   COMMENT '量程上限',
    is_active       TINYINT(1)      NOT NULL DEFAULT 1 COMMENT '是否启用，0=软删除',
    created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by      VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '创建人用户名（JPA Auditing 自动填充）',
    updated_by      VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '最后修改人用户名（JPA Auditing 自动填充）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_type_point (device_type_id, point_code),
    FOREIGN KEY (device_type_id) REFERENCES device_type(id)
) COMMENT '测点模板，策略A：device_type_point 是权威来源，设备测点统一从此读取';
```

**变更保护规则：**
- 新增测点：直接执行，立即对所有该类型设备生效
- 修改/删除测点：需前端带 `confirm=true` 二次确认，API 先返回影响设备数量
- 删除有历史数据的测点：仅软删除（`is_active = 0`），保留历史数据可查

### 2.4 device（设备）

设备实例，存档案信息，不存运行时状态（运行时状态在 device_status）。

```sql
CREATE TABLE device (
    id                  BIGINT          NOT NULL AUTO_INCREMENT,
    device_code         VARCHAR(50)     NOT NULL COMMENT '设备编码，业务唯一标识',
    name                VARCHAR(100)    NOT NULL COMMENT '设备名称',
    location            VARCHAR(200)    COMMENT '安装位置，如 A车间-1号产线',
    connect_id          VARCHAR(100)    NOT NULL COMMENT '接入标识，MQTT时=网关SN，TCP时=设备自定义标识，认证白名单依据',
    device_type_id      BIGINT          NOT NULL COMMENT '所属设备类型，profile 和测点均从此获取',
    lifecycle_status    ENUM('ACTIVE','INACTIVE') NOT NULL DEFAULT 'ACTIVE' COMMENT '生命周期：ACTIVE正常监控 / INACTIVE暂停监控',
    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    created_by          VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '创建人用户名（JPA Auditing 自动填充）',
    updated_by          VARCHAR(50)     NOT NULL DEFAULT 'system' COMMENT '最后修改人用户名（JPA Auditing 自动填充）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_device_code (device_code),
    UNIQUE KEY uk_connect_id (connect_id),
    FOREIGN KEY (device_type_id) REFERENCES device_type(id)
) COMMENT '设备实例，只存档案信息，运行时状态见 device_status';
```

**设计说明：**
- `profile_type` 不在设备表存储，通过 `device_type_id → device_type.profile_type` 获取，避免设备与类型的协议配置不一致
- `online_status` 不在设备表存储，独立维护于 `device_status` 表，避免高频更新影响核心业务表

### 2.5 device_status（设备实时状态）

每台设备一条记录，设备注册时自动创建，频繁 upsert，与 device 表分离。

```sql
CREATE TABLE device_status (
    device_id           BIGINT          NOT NULL COMMENT '设备 ID',
    online_status       ENUM('ONLINE','OFFLINE') NOT NULL DEFAULT 'OFFLINE' COMMENT '当前在线状态',
    connected_at        DATETIME(3)     COMMENT '最近一次连接建立时间，NULL=从未连接过',
    disconnected_at     DATETIME(3)     COMMENT '最近一次断开时间',
    last_seen_at        DATETIME(3)     COMMENT '最近一次有数据上报时间，不参与离线判定',
    updated_at          DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    PRIMARY KEY (device_id),
    FOREIGN KEY (device_id) REFERENCES device(id)
) COMMENT '设备实时连接状态，每台设备一条，注册时自动创建';
```

**初始值规则（设备注册时写入）：**

| 字段 | 初始值 | 说明 |
|------|------|------|
| online_status | OFFLINE | 从未连接过 |
| connected_at | NULL | NULL 表示"从未连接"，区别于"曾经在线现在离线" |
| disconnected_at | NULL | 同上 |
| last_seen_at | NULL | 从未有数据 |

**View 层状态展示逻辑：**

```
online_status = ONLINE                          → 在线
online_status = OFFLINE + connected_at IS NULL  → 从未连接
online_status = OFFLINE + connected_at NOT NULL → 离线
```

### 2.6 device_connectivity_log（在离线历史）

只追加不更新，每次设备离线产生一条记录，上线时回填恢复时间。

```sql
CREATE TABLE device_connectivity_log (
    id                  BIGINT          NOT NULL AUTO_INCREMENT,
    device_id           BIGINT          NOT NULL COMMENT '设备 ID',
    went_offline_at     DATETIME(3)     NOT NULL COMMENT '离线时间',
    came_online_at      DATETIME(3)     COMMENT '恢复时间，NULL=尚未恢复',
    offline_duration_s  INT             COMMENT '离线时长（秒），came_online_at 回填时计算',
    online_duration_s   INT             COMMENT '本次离线前的在线时长（秒），went_offline_at 时计算',
    cause               ENUM('MQTT_DISCONNECT','TCP_DISCONNECT','GATEWAY_REPORTED') NOT NULL COMMENT '离线原因',
    created_at          DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    INDEX idx_device_time (device_id, went_offline_at),
    FOREIGN KEY (device_id) REFERENCES device(id)
) COMMENT '在离线历史记录，仅追加，用于统计在线率等指标';
```

**统计查询支持（基于 online_duration_s + offline_duration_s 直接聚合）：**

```sql
-- 某设备某时段在线率
SELECT
    SUM(online_duration_s)  AS online_total_s,
    SUM(offline_duration_s) AS offline_total_s,
    COUNT(*)                AS offline_count,
    AVG(offline_duration_s) AS avg_offline_s,
    MAX(offline_duration_s) AS max_offline_s
FROM device_connectivity_log
WHERE device_id = ? AND went_offline_at BETWEEN ? AND ?;
```

### 2.7 telemetry_record（遥测数据）

时序数据核心表，高频写入，无外键约束，按月分区。

```sql
CREATE TABLE telemetry_record (
    id          BIGINT          NOT NULL AUTO_INCREMENT,
    device_id   BIGINT          NOT NULL COMMENT '设备 ID，软关联，无外键约束（避免写入锁竞争）',
    point_code  VARCHAR(50)     NOT NULL COMMENT '测点编码，写入前由 IngestService 校验是否在 device_type_point 中存在',
    ts          DATETIME(3)     NOT NULL COMMENT '采集端时间戳（毫秒精度），支持乱序写入',
    num_value   DOUBLE          COMMENT '数值型测点值，99% 场景使用此字段',
    str_value   VARCHAR(500)    COMMENT '字符串型测点值，极少数场景使用',
    PRIMARY KEY (id, ts),
    INDEX idx_device_point_ts (device_id, point_code, ts)
) COMMENT '遥测数据，按月分区，保留时长可配置'
PARTITION BY RANGE COLUMNS(ts) (
    PARTITION p202601 VALUES LESS THAN ('2026-02-01'),
    PARTITION p202602 VALUES LESS THAN ('2026-03-01'),
    -- 按月追加，到期 DROP PARTITION，不做 DELETE
    PARTITION p_future VALUES LESS THAN MAXVALUE
);
```

**设计说明：**
- 无外键：避免高频写入时的行锁竞争，数据完整性由 `TelemetryIngestService` 写入前校验保证
- 双值字段：`num_value`（DOUBLE）覆盖 99% 数值型传感器，`str_value` 覆盖字符串类型，避免全部存 VARCHAR 无法利用数值索引
- 乱序支持：以采集端 `ts` 入库，不使用服务器接收时间，Connect 断点续传的历史数据自动归位
- 分区策略：`DROP PARTITION` 比 `DELETE WHERE ts < cutoff` 快几个数量级，且不产生碎片

### 2.8 telemetry_latest（测点最新值）

每个测点永远只有一条记录，写入时 upsert 维护，专用于看板首屏加载和高频最新值查询场景。

```sql
CREATE TABLE telemetry_latest (
    device_id   BIGINT          NOT NULL COMMENT '设备 ID',
    point_code  VARCHAR(50)     NOT NULL COMMENT '测点编码',
    num_value   DOUBLE          COMMENT '数值型最新值',
    str_value   VARCHAR(500)    COMMENT '字符串型最新值',
    ts          DATETIME(3)     NOT NULL COMMENT '采集端时间戳（最新一条数据的时间）',
    updated_at  DATETIME(3)     NOT NULL COMMENT '本条记录的更新时间',
    PRIMARY KEY (device_id, point_code)
) COMMENT '测点最新值，每个测点一条记录，upsert 维护，不参与历史数据存储';
```

**设计说明：**
- 主键 `(device_id, point_code)` 保证每个测点唯一一条记录，查一台设备全部测点最新值为单次主键范围扫描
- 与 `telemetry_record` 分离：`telemetry_record` 负责历史存储，`telemetry_latest` 负责当前状态，职责清晰
- 不参与月分区，不参与数据保留策略，与历史数据生命周期无关

**乱序写入保护（断点续传场景）：**

Connect 补传历史数据时，时间戳早于当前最新值，此时不应覆盖最新值。upsert 语句加时间判断：

```sql
INSERT INTO telemetry_latest (device_id, point_code, num_value, str_value, ts, updated_at)
VALUES (?, ?, ?, ?, ?, NOW(3))
ON DUPLICATE KEY UPDATE
    num_value  = IF(VALUES(ts) > ts, VALUES(num_value),  num_value),
    str_value  = IF(VALUES(ts) > ts, VALUES(str_value),  str_value),
    ts         = IF(VALUES(ts) > ts, VALUES(ts),         ts),
    updated_at = IF(VALUES(ts) > ts, NOW(3),             updated_at)
```

只有新消息的采集时间戳严格大于已存储的时间戳，才执行更新。补传的历史数据正常写入 `telemetry_record`，但不更新 `telemetry_latest`。

### 2.9 system_config（系统配置）

系统级参数存储，KV 结构，启动时全量加载到内存。

```sql
CREATE TABLE system_config (
    config_key      VARCHAR(100)    NOT NULL COMMENT '配置键',

    updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
```

## 3. 表关系总览

```
protocol_profile ──┐
                   ├──< device_type ──< device_type_point
                   │         │
                   │         └──< device ──< device_status
                   │                   │
                   │                   ├──< device_connectivity_log
                   │                   │
                   │                   ├──< telemetry_record   （历史数据，按月分区）
                   │                   │
                   │                   └──< telemetry_latest   （最新值，每测点一条）

system_config（独立，无外键关联）

sys_user >--< sys_role（多对多，via sys_user_role）
sys_role  >--< sys_permission（多对多，via sys_role_permission）
```

**两张遥测表的职责对比：**

| | telemetry_record | telemetry_latest |
|------|------|------|
| 职责 | 历史数据存储 | 当前最新值 |
| 记录数 | 每条消息一行（持续追加） | 每个测点一行（upsert 更新） |
| 查询场景 | 历史曲线、数据分析、数据导出 | 看板首屏、实时状态展示 |
| 分区 | 按月分区 | 不分区 |
| 数据保留 | 遵循 retention_days 策略 | 永久保留（始终是最新值） |
| 乱序保护 | 以采集端 ts 入库，天然支持 | upsert 时判断 ts 新旧，补传数据不覆盖 |

## 4. 索引策略

| 表 | 索引 | 用途 |
|------|------|------|
| device | uk_connect_id | 认证时快速查找设备 |
| device | uk_device_code | 业务查询 |
| device_status | PRIMARY (device_id) | 状态查询，一台设备一条 |
| device_connectivity_log | idx_device_time | 历史记录分页查询 |
| telemetry_record | idx_device_point_ts | 历史曲线、最新值查询 |
| telemetry_latest | PRIMARY (device_id, point_code) | 最新值查询，单次范围扫描 |
| sys_user | uk_username | 登录查找 |
| sys_role | uk_role_code | 角色编码查找 |
| sys_permission | uk_perm_code | 权限码查找 |
| sys_user_role | PRIMARY (user_id, role_id) | 用户角色查找 |
| sys_role_permission | PRIMARY (role_id, perm_id) | 角色权限查找 |
