## 1. 设计原则

- 所有基类放在 `edgeinsight-common` 模块，所有其他模块均可引用
- 实体基类使用 JPA `@MappedSuperclass`，不映射为独立表
- 审计字段（`createdBy` / `updatedBy`）通过 Spring Data JPA Auditing 自动填充，不需要 Service 层手动赋值
- `BaseService` 只封装通用模式，不强制所有 Service 都继承，特殊 Service（如 `TelemetryIngestService`）直接实现业务接口

## 2. 实体基类

### 2.1 BaseEntity（基础实体）

所有数据库实体的根基类，包含主键和时间戳字段。

```java
@MappedSuperclass
@EntityListeners(AuditingEntityListener.class)
public abstract class BaseEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @CreatedDate
    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @LastModifiedDate
    @Column(name = "updated_at", nullable = false)
    private LocalDateTime updatedAt;
}
```

### 2.2 AuditableEntity（可审计实体）

在 `BaseEntity` 基础上追加操作人字段，适用于需要记录"谁操作"的业务实体。
审计字段通过 `AuditorAware` 从当前登录用户的 `SecurityContext` 自动获取，无需 Service 层手动赋值。

```java
@MappedSuperclass
public abstract class AuditableEntity extends BaseEntity {

    @CreatedBy
    @Column(name = "created_by", nullable = false, updatable = false)
    private String createdBy;      // 创建人用户名

    @LastModifiedBy
    @Column(name = "updated_by", nullable = false)
    private String updatedBy;      // 最后修改人用户名
}
```

### 2.3 各实体继承关系

| 实体类 | 继承 | 说明 |
|------|------|------|
| `Device` | `AuditableEntity` | 需要记录谁注册、谁修改 |
| `DeviceType` | `AuditableEntity` | 需要记录谁创建模板 |
| `DeviceTypePoint` | `AuditableEntity` | 需要记录谁配置测点 |
| `ProtocolProfile` | `AuditableEntity` | 需要记录谁维护协议档案 |
| `SysUser` | `AuditableEntity` | 需要记录谁创建用户 |
| `SysRole` | `AuditableEntity` | 需要记录谁创建角色 |
| `SysPermission` | `BaseEntity` | 权限码由研发维护，只需时间戳 |
| `DeviceStatus` | 不继承 | 无主键自增，以 device_id 为主键 |
| `DeviceConnectivityLog` | `BaseEntity` | 只追加，需要 id 和 created_at |
| `TelemetryRecord` | 不继承 | 高频写入表，不使用 JPA 实体操作 |
| `TelemetryLatest` | 不继承 | upsert 操作，不使用 JPA 实体 |
| `SystemConfig` | 不继承 | 以 config_key 为主键，无自增 id |

**说明：** `TelemetryRecord` 和 `TelemetryLatest` 为高频写入表，通过 `TelemetryRepository` 的自定义 SQL/JPQL 操作，不走 JPA 实体的标准生命周期，不继承基类以避免不必要的字段映射。

### 2.4 JPA Auditing 配置

```java
// edgeinsight-app 启动类或配置类
@EnableJpaAuditing
@SpringBootApplication
public class EdgeInsightApplication { ... }

// edgeinsight-core 中实现 AuditorAware，从 SecurityContext 获取当前用户
@Component
public class SecurityAuditorAware implements AuditorAware<String> {
    @Override
    public Optional<String> getCurrentAuditor() {
        // 从 JwtAuthFilter 写入的 SecurityContext 中获取当前用户名
        // 未登录时（公开接口）返回 "system"
        return Optional.of(getCurrentUsername());
    }
}
```

## 3. 公共响应封装

放在 `edgeinsight-common/dto/` 下。

### 3.1 Result（统一响应）

```java
public class Result<T> {
    private int    code;
    private String message;
    private T      data;

    public static <T> Result<T> ok(T data) {
        return new Result<>(200, "success", data);
    }

    public static <T> Result<T> ok() {
        return new Result<>(200, "success", null);
    }

    public static <T> Result<T> fail(int code, String message) {
        return new Result<>(code, message, null);
    }
}
```

**错误码约定：**

| code | 含义 | 触发场景 |
|------|------|------|
| 200 | 成功 | 正常响应 |
| 400 | 请求参数错误 | 参数校验失败（Hibernate Validator） |
| 401 | 未认证 | Token 缺失、过期、非法 |
| 403 | 无权限 | Token 有效但权限不足 |
| 404 | 资源不存在 | 查询的记录不存在 |
| 409 | 数据冲突 | 唯一键冲突（如 device_code 重复） |
| 500 | 服务器内部错误 | 未捕获异常 |

### 3.2 PageResult（分页响应）

```java
public class PageResult<T> {
    private long    total;     // 总记录数
    private List<T> list;      // 当前页数据

    public static <T> Result<PageResult<T>> ok(Page<T> page) {
        PageResult<T> result = new PageResult<>();
        result.setTotal(page.getTotalElements());
        result.setList(page.getContent());
        return Result.ok(result);
    }
}
```

### 3.3 BaseQuery（分页查询基类）

```java
public class BaseQuery {
    @Min(1)
    private int pageNum  = 1;

    @Min(1)
    @Max(500)
    private int pageSize = 20;

    public Pageable toPageable() {
        return PageRequest.of(pageNum - 1, pageSize);
    }
}
```

所有分页查询的请求体 DTO 继承 `BaseQuery`，自动获得 `pageNum` / `pageSize` 参数和 `toPageable()` 转换方法。

## 4. 服务基类

放在 `edgeinsight-core/domain/base/` 下。

### 4.1 BaseService（通用服务接口）

```java
public interface BaseService<T, ID> {
    T       getById(ID id);                      // 查询单条，不存在抛 NotFoundException
    List<T> list();                              // 查询全部（适合数据量小的配置类）
    T       save(T entity);                      // 新增
    T       update(T entity);                    // 更新
    void    removeById(ID id);                   // 删除（物理删除）
}
```

### 4.2 BaseServiceImpl（默认实现）

```java
public abstract class BaseServiceImpl<T extends BaseEntity,
                                       ID,
                                       R extends JpaRepository<T, ID>>
        implements BaseService<T, ID> {

    protected final R repository;

    protected BaseServiceImpl(R repository) {
        this.repository = repository;
    }

    @Override
    public T getById(ID id) {
        return repository.findById(id)
            .orElseThrow(() -> new NotFoundException("记录不存在: " + id));
    }

    @Override
    public T save(T entity) {
        return repository.save(entity);
    }

    @Override
    public T update(T entity) {
        getById((ID) entity.getId()); // 先确认存在
        return repository.save(entity);
    }

    @Override
    public void removeById(ID id) {
        getById(id); // 先确认存在
        repository.deleteById(id);
    }
}
```

具体 Service 继承 `BaseServiceImpl` 后，直接获得基础 CRUD 能力，只需覆写有差异的方法（如带业务校验的删除）：

```java
@Service
public class DeviceTypeServiceImpl
        extends BaseServiceImpl<DeviceType, Long, DeviceTypeRepository>
        implements DeviceTypeService {

    // 直接继承 getById / save / update
    // 只覆写删除，加业务校验
    @Override
    public void removeById(Long id) {
        long count = deviceRepository.countByDeviceTypeId(id);
        if (count > 0) {
            throw new BusinessException("该类型下有 " + count + " 台设备，无法删除");
        }
        super.removeById(id);
    }
}
```

## 5. 公共异常体系

放在 `edgeinsight-common/exception/` 下。

```
BusinessException       业务异常，code=400，由 Service 层主动抛出
NotFoundException        资源不存在，code=404，由 BaseServiceImpl.getById 抛出
ForbiddenException       无权限，code=403，由 PermissionAspect 抛出
UnauthorizedException    未认证，code=401，由 JwtAuthFilter 抛出
```

统一由 `GlobalExceptionHandler`（`@RestControllerAdvice`）捕获并转换为 `Result` 响应，Controller 层不需要 try-catch。

## 6. 各实体继承关系总结

以上继承关系决定了 DDL 中哪些表需要携带 `created_by` / `updated_by` 字段。所有字段均已在 **文档 02（数据库设计）** 和 **文档 08（用户权限与 JWT 设计）** 对应表的 DDL 中完整定义，以这两份文档为唯一 DDL 来源。
